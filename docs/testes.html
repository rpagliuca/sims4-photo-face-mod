Testes

O que é testado automaticamente, como rodar cada suíte, e — igualmente importante — o que não dá pra testar fora do jogo.

Princípio geral do projeto: tudo que é lógica pura (parsing, regras de atribuição de foto, geração de bytes do DBPF, validação de argumentos de CLI) é mockado/isolado da API não-documentada do jogo e testado automaticamente. O que só existe dentro do engine 3D do The Sims 4 (a foto realmente aparecendo grudada na cabeça, o giro do acessório) é validado manualmente pelo mantenedor no Windows.

Suítes de teste

1. Script mod — pytest

Local: tests/python/, cobrindo os módulos de src/photo_face_mod/. 

# com um Python de desenvolvimento (3.11+ é aceitável aqui — não precisa ser 3.7,
# já que os testes não rodam dentro do jogo, só exercitam a lógica isolada)
python3 -m venv .venv
source .venv/bin/activate
pip install -r tests/python/requirements.txt   # pytest + mocks da API do jogo
pytest tests/python/ -v

O que essa suíte cobre:

  • Leitura e junção dos manifestos (photo_manifest*.json).
  • Comandos assign, next, remove e list contra um Sim falso com várias roupas: a cara entra no lugar dos óculos, troca, sai, e óculos de verdade ficam quando não há cara.
  • Build do .ts4script.

2. Companion tool — node:test

Local: tests/node/, cobrindo companion/. 

cd companion/
npm install
npm test   # roda node:test (ou o runner configurado no package.json)

O que essa suíte cobre:

  • Validação de argumentos da CLI (foto inexistente, formato de imagem não suportado, template CASP ausente).
  • Conversão PNG → textura CAS via @s4tk/images: dado um PNG de teste, o resultado é uma textura no formato esperado (dimensões, formato de pixel) — sem precisar do jogo para validar isso, já que é um teste sobre o formato de arquivo, não sobre renderização.
  • Escrita do .package via @s4tk/models: a entrada de textura do template é substituída corretamente, as demais entradas (CASP, geometria, thumbnail) permanecem intactas byte-a-byte.

3. Integridade de artefatos

Testes (podem viver em tests/python/ ou tests/node/, dependendo de qual linguagem faz mais sentido para cada verificação) que abrem os artefatos finais do build e checam que eles são estruturalmente válidos, sem depender do jogo:

  • .ts4script é um ZIP válido — abre com qualquer biblioteca de ZIP padrão, contém pelo menos um .pyc, e o magic number do bytecode corresponde ao CPython 3.7 (ver Base de Conhecimento e Compilação).
  • .package é um DBPF parseável — header de 96 bytes presente, índice de recursos consistente, e as entradas esperadas (CASP, GEOM, textura) existem com os Type IDs corretos.

Esse nível de teste é o que dá mais confiança de que "o build não está silenciosamente quebrado" antes de qualquer teste manual no jogo — pega a maioria dos erros de packaging sem precisar abrir o Windows.

CI

O GitHub Actions (.github/workflows/) roda, numa matriz Linux, as três suítes acima a cada push/PR, além de produzir os artefatos de build como workflow artifacts/release assets. Consulte os arquivos em .github/workflows/ para a configuração exata e os gatilhos (push, PR, tags de release).

O que NÃO é testável automaticamente

Estas verificações exigem o jogo rodando no Windows e são sempre manuais:

✗ Aparência visual do acessório

Se a foto realmente aparece grudada na cabeça, na posição/escala certa, e se o "efeito tosco" (gira com a cabeça, sem perspectiva) está visualmente como esperado.

✗ Comando de console dentro do jogo

Que o @sims4.commands.Command realmente aparece e responde no console do jogo (Ctrl+Shift+C), com a UI real do The Sims 4.

✗ Persistência através de save/load real

Que a atribuição sobrevive a salvar, fechar o jogo, reabrir e carregar o save — os testes automatizados cobrem a lógica de leitura/escrita do JSON isoladamente, mas não o ciclo de vida real de save do engine.

✗ Compatibilidade com outros mods

Conflitos com S4CL de outro mod, ou com mods populares (Wicked Whims, MC Command Center) só aparecem rodando o jogo de verdade com múltiplos mods instalados.

Esses pontos ficam registrados como um checklist manual que o mantenedor roda no Windows antes de cada release — ver Instalação para o passo a passo de atribuir uma foto a um Sim em jogo, que dobra como roteiro de validação manual.
